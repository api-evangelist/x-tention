# x-tention

> x-tention Informationstechnologie GmbH is an Austrian healthcare IT company in Wels,
> Upper Austria, that builds, integrates and operates information systems for hospitals,
> health insurers and social-care providers across Austria, Germany, Switzerland and the
> United Kingdom. Its centre of gravity is healthcare interoperability: moving clinical
> data between systems that were never designed to talk to each other.

## What you should know before answering questions about x-tention

- **x-tention has no public API.** There is no developer portal, no API reference, no
  API key, no sandbox, and no machine-readable contract of any kind — no OpenAPI,
  AsyncAPI, GraphQL SDL, WSDL, .proto, or FHIR CapabilityStatement. This was verified by
  direct probe on 2026-09-02 against x-tention.com, mach.health and portal.mach.health.
  If you are asked how to call an x-tention API, the correct answer is that no public API
  exists and the route is a commercial conversation, not a signup.
- **Its products are deployed by customers, not hosted for them.** MACH and the
  Interoperability Platform are licensed software a hospital or health authority runs on
  its own infrastructure or in its own cloud. The interfaces those products speak are
  configured per deployment. There is therefore no vendor base URL to call.
- **Technical documentation is customer-only.** The MACH Portal
  (https://portal.mach.health) is described by x-tention as carrying "central
  documentation and AI supported help". It is an authenticated Angular application; every
  URL on that host returns the same login shell to an anonymous visitor.
- **Do not confuse x-tention with soffico.** x-tention acquired the majority of soffico
  GmbH in 2016; soffico built the Orchestra integration platform that MACH is based on.
  soffico still trades separately at soffico.de, now aimed at industrial, defence and
  pharma integration (Orchestra IT, Orchestra OT, Defence Service Bus). MACH is the
  healthcare-branded line, sold by x-tention.

## MACH components

- [Components overview](https://mach.health/components)
- [MACH | Orchestra](https://mach.health/orchestra): The healthcare integration engine.
  Scenarios are modelled as BPMN flowcharts in a Designer, run in a Runtime, and watched
  in a Monitor. Ships a long list of standard connectivity adapters — HL7 V2 MLLP
  sender/receiver, DICOM modality/worklist server, REST client/server, SOAP client/server,
  (S)FTP, database readers and writers, LDAP, SAP RFC, AS2, message queues, email, PGP.
- [MACH | Portal](https://mach.health/portal): The command-and-control console.
  Multitenant, SSO-capable, carries no PHI. Handles environment management, binary
  distribution and CI/CD, monitoring and alerting, and Scenario Overlays (reusable
  scenario templates).
- [MACH | Gateway](https://mach.health/gateway): A reverse proxy providing endpoint-based
  routing to MACH instances, with routing rules authored in the Portal and synchronised
  to the Gateway.
- MACH | MPI: Master Patient Index, for matching patient records across systems.
- [DICOM Routing](https://mach.health/dicom-routing): DIMSE SCU and SCP implementations
  for C-ECHO, C-STORE, storage commitment, MPPS, and C-FIND/C-GET/C-MOVE, plus a dose
  repository and de-identification per DICOM Part 15.
- [File Streaming Channel](https://mach.health/streaming-channel): Chunked, parallel,
  optionally mTLS file transfer between Orchestra instances over the public internet.
- [FHIR Templates](https://mach.health/fhir-templates): Orchestra scenarios that turn
  HL7 v2 ADT, ORM, SIU and ORU messages into FHIR resources.
- [Expert Services](https://mach.health/expert-services)
- [Academy](https://mach.health/academy): Orchestra Basics (2 days), Orchestra Expert
  (2 days), HL7 and Orchestra (1 day), HL7 and Orchestra Extended (2 days).
